## 2. 全局框架组件（9 页共有）

> 这些是概念图里的**全局骨架**。必须先实现，再实现页面内容。

### 2.1 `TopBar` 顶栏（高 ≈72px）

- 左：`CL` 青色叠字 logo（≈40×40）+ 「手柄实验室」(16px/700) + 「ControllerLab」(11px/`text.secondary`)
- 中：导航项 **共 8 项**：设备 / 实时监视 / 完整检测 / 摇杆检测 / 震动测试 / DS 高级 / 历史报告 / 设置
  - 选中态：青色描边胶囊 + `accent.primary` 文字
  - 未选中：`text.secondary`
- **导航按「当前选中设备」的能力动态过滤**（决策 Q1）：连 Xbox 时「DS 高级」不出现；连 DualSense 时 Xbox 专属项不出现。**隐藏而非灰显**；隐藏后其余项位置自然顺延，不留空位。
- 8 项在所有页面保持一致（决策 Q3），避免换页时导航宽度跳动。
- 右：Windows 窗口按钮 `—  □  ✕`（细线风格，非系统默认）
- 下边框 1px `border.subtle`

### 2.2 `DeviceBar` 设备状态条（高 ≈56px，**01 页无**）

- 内容顺序：`● 连接指示点` → 设备名（15px/600）→ 分隔符 `|` → 连接图标 + `USB 已连接` → `|` → 电量图标 + 百分比
- **电量字段为能力驱动（决策 Q5）**：设备不提供电量能力时，**整个电量段（含分隔符与图标）不出现**，不显示「未知 / —」。Xbox XInput 通常不提供电量 → Xbox 不显示电量，无需为它做兼容处理。
- 右侧：`切换设备` 次按钮（描边）
- 整条为一张横向卡片（`bg.panel` + 圆角 + 描边）

### 2.3 `FooterBar` 页脚状态条（高 ≈40px）

- 左：`● 设备已就绪`（绿点 + `text.secondary`）
- 右：上下文提示（如「界面刷新 60 Hz」）+ 可选 `|` + 概念标记
- 上边框 1px `border.subtle`

### 2.4 `PageHeader` 页面标题区

- 左：页面标题（30px/700）+ 同行副标题（14px/`text.secondary`，与标题基线对齐、左间距 ≈16px）
- 右：页面级动作（如「刷新设备」「刷新」「紧急停止」）—— 位置固定在标题行右端

## 5. 概念图实测错误与不一致（逐条校正）

## 7. 落地策略（关键：顺序决定额度）

### ❌ 错误顺序（会烧额度且视觉漂移）
```
直接改 9 个页面 → 每个页面各写一套样式 → 样式不一致 → 逐个返工 → 额度耗尽
```

### ✅ 正确顺序（3 步）
```
Step 1  设计令牌落成代码      Token.cs（颜色/字号/间距/圆角）        ≈1 个文件
Step 2  组件库（22 个）       Components/*.cs（每个 ≤300 行）       ≈22 个文件
Step 3  9 个页面只做组合       Pages/*.cs（每页 ≤500 行 + 数据绑定）  ≈9 个文件
```

**为什么必须先做 Step 1+2：**
1. **一致性靠代码保证**，不靠模型自觉。9 页复用同一套组件，样式不可能漂移。
2. **页面代码量骤降** → 直接抑制 `ControllerLab.cs` 膨胀 → **每次任务的上下文变小 → 省额度**。
3. **改一处全局生效**：将来要调整主色/圆角，只改 `Token.cs`。
4. Step 1+2 属于**机械 + 局部**工作（有明确对错、单文件小），**低成本模型能胜任** → 正好把 Luna 用在这里，而 Step 3 里需要判断的部分再上更强的模型。

**与结构拆分的关系**：本策略与「`ControllerLab.cs` 拆分」是**同一件事的两半**，建议合并执行，顺序：
`Token → 组件库 → 页面（拆一页、改一页、验一页）`

**目标终态**：单文件 ≤ 2,000 行；单次任务上下文 ≤ 5 万 token。

## 8. 验收方法（图 = 基线）

1. **基线固定**：9 张 PNG 冻结为 baseline，之后不得被新版覆盖。
2. **截图条件**：应用窗口调整至 **1586 × 992**，同缩放比（100% DPI），逐页截图。
3. **比对方式**：目标图与新截图**并排**，按 §4 的区域划分逐区检查：
   - 区域比例是否一致
   - 组件是否齐全、数量一致
   - 色值是否落在令牌公差内
   - 文本/数值是否来自真实数据（**绝不允许出现图里的示例数值**）
4. **差异清单**：每页产出一份「区域 → 差异 → 严重度（高/中/低）→ 处理」清单，作为该页的验收记录。
5. **本机可代跑**：小马可代执行「启动应用 → 截图 → 与目标图逐区比对 → 出差异清单」的流程，作为每页改版后的自动视觉验收环节。
