# ControllerLab 改版实现规格 · 状态矩阵

> **用途**：把「9 页视觉概念图 + Astra 提示词」降维成**可直接执行的实现规格**，供低成本模型（Luna 等）按页施工，避免它自己脑补状态。
>
> **来源**：`Documents\手柄\ControllerLab-改版方案\`（9 张概念图 + 生成提示词 + 校正提示词），配合项目 `docs/PROJECT_STATUS.md`、`AGENTS.md` 与源码实况。
>
> **边界**：本文档只描述**行为与状态**，不定美术像素；不授权任何新硬件能力；不授权改动已校准 Overlay 坐标与真实 PNG 遮罩。
>
> **数量缺口**：概念图 = 9 个状态（每页 1 张代表图）｜实现需要 = 本文档 **9 页 × 状态矩阵**（约 **127 条** 状态条目）。

---

## 0. 如何使用本文档（给 AI 的执行约定）

1. **一次一页**。不要把 9 页塞进同一个任务。一次只实现一个页面，完成并自检后再开下一页。
2. **开工前必读**：`AGENTS.md` → `docs/PROJECT_STATUS.md` → 本页对应的 `docs/*.md` → `git status -sb`。
3. **收工前必做**：构建全解决方案 → 跑本页相关自检 → 回归 Xbox 与 DualSense 原有功能 → 更新 `PROJECT_STATUS.md` → 列改动文件 + 实机验证状态 → 一次清晰提交。
4. **本页交付 = 该页所有状态全部可达**，不是"把概念图画出来"。状态缺失视为未完成。
5. **不得新增**概念图与本文档均未提及的功能、快捷键、设置项或云端能力。
6. **不确定就停**，标记 `NEEDS-OWNER` 并写进提交说明 —— 不要自行编造合理化的行为。

### 状态编号约定

- `S0`–`S13`：全局状态（见第 1 节），所有页面共用同一编号。
- 页面条目形如 `03/B`：第 03 页的第 B 条状态。

## 1. 全局状态机

### 1.1 状态定义

| 编号 | 状态 | 含义 | 典型触发 |
| --- | --- | --- | --- |
| **S0** | 启动加载 | 应用启动、枚举设备中 | 进程启动、页面首次构造 |
| **S1** | 无设备 | 未发现任何受支持设备 | 枚举完成但无设备、全部断开 |
| **S2** | 单设备空闲 | 1 台设备在线且无采样/输出 | 连接、采样结束 |
| **S3** | 多设备待选 | ≥2 台在线，尚未确定目标 | 第二台接入 |
| **S4** | 输入活跃 | 收到真实输入报告（`HasRealInput`） | 用户按键/推杆 |
| **S5** | 采集中 | 独占型采样进行中（静止/圆周/回中/向导步） | 点击"开始采样" |
| **S6** | 采样取消 | 用户主动取消采样 | 点击取消/离开页面 |
| **S7** | 采样完成 | 有本轮结果 | 采样到时长/步骤走完 |
| **S8** | 设备断开 | 运行中掉线 | HID/XInput 报告停流、拔出、蓝牙断 |
| **S9** | 设备重连 | 断开设备重新出现 | 同设备 ID 重新枚举 |
| **S10** | 能力不支持 | 当前设备无此能力 | 设备类型判定 |
| **S11** | 功能未开放 | 已实现但未实机验证 / 未解析 | 灯带 RGB、自适应扳机输出 |
| **S12** | 错误 | 驱动/解析/写入失败 | HID 打开失败、解析异常、写入拒绝 |
| **S13** | 互斥阻塞 | 被另一独占操作挡住 | 震动运行中、校准进行中 |

### 1.2 状态优先级（同时成立时，谁先显示）

```
S12 错误  >  S8 断开  >  S13 互斥阻塞  >  S5 采集中  >  S6 取消  >  S7 完成  >  S4 输入活跃  >  S3 多设备待选  >  S1 无设备  >  S2 空闲  >  S0 加载
```

**规则**：低优先级状态不得覆盖高优先级状态的表现。例如采样中设备断开 → 显示 S8，采样必须作废（不可显示 S7 完成）。错误态必须带可读原因，不得只显示"失败"。

### 1.3 状态迁移触发源（三处必须一致）

| 触发源 | 必须驱动的状态更新 |
| --- | --- |
| 设备枚举/热插拔 | S1 / S2 / S3 / S8 / S9 |
| 输入报告流 | S2 / S4（静默超时回落 S2） |
| 独占操作生命周期 | S5 / S6 / S7 / S13 |

**注意**：概念图只画了"结果态"，**没有任何一张图覆盖 S0/S5/S6/S8/S12/S13** —— 这 6 类是最高频的真实状态，最容易被漏掉。

## 2. 全局不变量（任何页面、任何改动都不得破坏）

### 2.1 安全（震动）

1. 默认强度 ≤ 40%，默认时长 ≤ 5 秒，单次连续播放 ≤ 30 秒。
2. 以下任一事件必须**停止并归零**输出：离开页面、设备断开、设备切换、应用退出、进入独占采样。
3. 震动与「摇杆静止漂移采样」「陀螺仪静止校准」「完整检测的静止步骤」**运行时互斥**（S13）。
4. 停止后 UI 必须显示「当前已停止 · 输出 0%」，不得残留"运行中"视觉。
5. **不得**因为改版引入新的定时器驱动震动停止路径（见第 5 节陷阱 A）。

### 2.2 真实性（不伪造）

1. 按键/摇杆/扳机/触摸/运动数据**只能来自真实输入报告**，`HasRealInput == false` 时不可计入。
2. 任何"演示/自检/构造数据"**不得写入正式检测结果、健康评分、历史报告**。
3. 未实机验证的能力必须保持"已实现但待实机验证"标注；UI 不得暗示已验证。
4. 概念图中的数值（电量 82%、中心偏移 0.8%、已完成 10/14 等）**全部是示例**，实现时必须换成真实数据源；没有数据源就显示"无数据"，**不得保留示例值**。
5. 跳过项显示「未检测」，**不参与评分**，且不得生成"完整健康结论"。
6. 「自适应扳机」「灯带」保持禁用态与锁定图标，**不发送任何未验证报告**。

### 2.3 Overlay 与素材

1. 已校准的 Overlay 逻辑坐标、默认区域、真实 PNG 遮罩**不得修改**。
2. 不得从概念图反向提取、重绘或替换手柄照片与遮罩。
3. 视觉改版只能改 UI 容器与皮肤，**不得动 Overlay 的坐标系**。
4. 用户校准 override 仍写入 LocalAppData，**不覆盖默认资源**。

### 2.4 数据与隐私

1. 设置、报告、震动配置、日志只写 `%LocalAppData%\ControllerLab` 及子目录。
2. 界面**不得显示完整本地路径**；使用设置页「打开数据目录」入口。
3. 报告仍为 **JSON + Markdown** 双格式，历史支持查看/删除/重新检测/导出/比较。

### 2.5 导航

1. 顶部主导航**共 8 项**：`设备 / 实时监视 / 完整检测 / 摇杆检测 / 震动测试 / DS 高级 / 历史报告 / 设置`，所有页面保持一致。
2. 「设备首页」同时可从 **顶栏「设备」项、logo、设备选择器**进入；「按键检测」从 **实时监视**进入。
3. **导航按「当前选中设备」的能力动态过滤**（决策 Q1，与现有行为一致）：连 Xbox 时不出现「DS 高级」；连 DualSense 时不出现 Xbox 专属项。**隐藏而非灰显**，其余项顺延不留空位。多设备同时在线时跟随当前选中设备（Q6 待确认）。
4. 手柄导航：`B` 返回设备首页，`LB/RB` 切页，`View + Menu` 进入可用操作。
5. 页面切换**不得**重复启动输入线程。

## 5. 已知工程陷阱（务必写进任务提示）

### 陷阱 A：刷新率设置可能复活已修复的崩溃

2026-09-20 修复的崩溃根因是 `DispatcherTimer → SetTimer` 路径耗尽 Window Manager timer handles，修复方式是改用受显示刷新率约束的 `CompositionTarget.Rendering`。

**风险**：09 设置页新增「界面刷新率 20/30/60 Hz」，如果实现成**定时器节流**，会直接复活该崩溃。

**要求**：刷新率必须实现为 `CompositionTarget.Rendering` 内的**帧跳过（frame skipping）**，禁止引入 `DispatcherTimer` / `SetTimer` 驱动 UI 刷新。改完必须做 ≥25 秒句柄趋势检查。

### 陷阱 B：不要让视觉改版把巨型文件撑得更大

当前 `ControllerLab.cs` 约 **601 KB / 11,036 行 / 47 个类**。9 页 UI 全部在代码式 WPF 中重写会显著推高该文件体积，直接放大每次任务的上下文成本与改坏风险。

**要求**：**先做结构拆分，再做视觉改版**。目标：单次任务所需上下文 ≤ 约 5 万 token；单文件 ≤ 约 2,000 行。拆分属机械工作，可用低成本模型完成。

### 陷阱 C：状态缺口会被模型自行脑补

概念图每页仅 1 个代表状态。若任务提示里不给状态清单，模型会按"顺利路径"实现，断开/取消/错误/互斥全部缺失，后续补做等于干两遍。

**要求**：把第 3 节对应页面的整张状态表**贴在任务提示里**，并明确"本页交付 = 该页所有状态可达"。
