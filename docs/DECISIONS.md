# 设计决策记录

## 已确认决策

### D-001：保持 WPF 原生实现

- **决策：** 保持 .NET Framework 4.8 的原生、代码式 WPF；不迁移 WebView、HTML/CSS、Unity 或浏览器渲染。
- **原因：** 当前输入、Raw Input、HID、XInput、渲染和校准均建立在原生桌面架构上。

### D-002：Xbox 与 DualSense 共享状态模型，但保留独立输入适配

- **决策：** UI 读取 `ControllerState`；Xbox 继续经 `InputManager` / XInput，DualSense 继续经 Raw Input 与 `SonyInputManager`。
- **原因：** 统一设备列表、检测页和报告，同时不抹平 DualSense 触摸 / 运动等专属能力。

### D-003：Overlay 使用统一逻辑舞台

- **决策：** Xbox 与 DualSense 各自以 1536 × 1024 底图坐标舞台绘制，底图和 Overlay 共用整体缩放。
- **原因：** 避免窗口尺寸、DPI 或单控件布局造成区域错位。

### D-004：真实 PNG Alpha Mask 优先于近似几何

- **决策：** 对 Xbox 顶部左右真实硬件区域使用 `LeftTopTriggerMask.png` / `RightTopTriggerMask.png`；不回退为矩形、近似 Path 或临时 Bézier 补丁。
- **原因：** 真实遮罩保留照片透视与硬件边缘，减少长期手工几何校准误差。

### D-005：USB 与蓝牙输出报告分开处理

- **决策：** DualSense USB 使用独立输出布局，蓝牙使用独立报告、序列和 CRC；禁止交叉发送。
- **原因：** 两种 HID 输出格式、长度与校验要求不同，混用可能导致错误输出或设备异常。

### D-006：震动与静止检测互斥

- **决策：** 漂移静止检测期间禁止启动震动；震动运行和停止后短等待窗口内禁止开始漂移检测。
- **原因：** 机械震动会污染静止漂移样本。陀螺仪静止校准也应采用同样保护规则。

### D-007：未实机验证不宣称已支持

- **决策：** 逻辑自检、动态演示、截图和构造报告不得替代真实硬件验证。
- **原因：** HID 报告、驱动、连接模式与输出写入在真实设备上存在差异。

### D-008：保留实时页底部扳机曲线

- **决策：** LT / RT 的最近 5 秒历史曲线保留为实时诊断的一部分，不替换为简单进度条。
- **原因：** 曲线提供峰值、回零、稳定性和输入变化等信息。

### D-009：硬件分析算法与 UI 解耦

- **决策：** 漂移、范围、触点、姿态和震动控制放在核心服务 / 模型中，UI 不直接读 HID / XInput。
- **原因：** 便于 Xbox 与 DualSense 共用检测逻辑、做自检并避免 UI 线程阻塞。
